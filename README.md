# Pretzel Labs — landing page

Восстановленная и оптимизированная главная страница Pretzel Labs плюс design-кит,
по которому другие люди собирают остальные разделы.

**Прод:** https://dist-tau-pink-9alr0jqy71.vercel.app

---

## Структура

```
export/            исходный экспорт Claude Design (.dc.html + support.js + ассеты).
                   Не менялся. Это источник правды по дизайну.
dist/              продакшен-сборка. Это то, что задеплоено.
build/             промежуточные артефакты сборки, оставлены для истории (см. «Как собрано»)
pretzel-labs-kit/  design-кит для команды: DESIGN.md, tokens.css, starter.html, ассеты, шрифты
tools/             одноразовые патч-скрипты, которыми правился dist (см. «История правок»)
serve.js           статический сервер с brotli и кеш-заголовками
```

## Запуск

```bash
node serve.js 4323          # оптимизированная сборка   -> http://localhost:4323
python3 -m http.server 4321 --directory export   # оригинал, для сравнения
```

Design-кит открывается сам по себе:

```bash
python3 -m http.server 4324 --directory pretzel-labs-kit   # -> /starter.html
```

## Деплой

```bash
npx vercel deploy dist --prod --yes
```

Конфиг Vercel лежит в `dist/vercel.json` (immutable-кеш на ассеты и шрифты, no-cache на HTML).
Проект в Vercel называется `dist` — имя досталось от папки, его стоит переименовать.

## Как собрано

Оригинал — документ Claude Design: HTML-шаблон + React-компонент, который рантайм
`support.js` рендерит в браузере, подтягивая React с unpkg. То есть до первой отрисовки
нужно было скачать и выполнить сторонний JS.

Сборка `dist/` получена так:

1. **Снятие отрисованного DOM.** Страница открывалась в браузере, React отрабатывал,
   после чего снимался готовый DOM (`build/snapshot.html`). Отдельно из CSSOM извлекались
   9 правил `.scpN:hover` — их не было в `outerHTML`, и без них терялись все ховеры.
2. **Замена рантайма.** React + `support.js` (~330 КБ) заменены на `dist/app.js` (~4 КБ)
   на ванильном JS. Это оказалось безопасно, потому что интерактив измерили заранее:
   между шагами блока «How it works» меняется **8 узлов из 368**, а ховер вообще не трогает
   DOM — он чисто CSS.
3. **Ассеты.** Каждый файл подбирался автоматически по двойному критерию: минимальный
   размер при SSIM ≥ 0.98 к оригиналу. Четыре JPEG оставлены как есть — WebP при том же
   качестве выходил больше.
4. **Патчи.** Дальше на `dist/index.html` последовательно накатывались скрипты из `tools/`.

Шаг 1 выполнялся вручную через браузер и **не заскриптован** — полностью воспроизводимой
сборки из `export/` нет. Артефакт — это `dist/`, он и коммитится.

## Результат

Замерено в headless Chrome через CDP, кеш отключён, по 3 прогона, медиана:

| | оригинал | dist |
|---|---|---|
| Десктоп FCP / LCP | 804 / 804 мс | **124 / 124 мс** |
| Мобильный FCP (медленный 4G + CPU ×4) | 3352 мс | **416 мс** |
| Мобильный LCP | 3352 мс | **1408 мс** |
| TBT | 6–71 мс | 0 мс |
| Трафик | 5137 КБ | 546 КБ |
| Запросов | 41 (16 кросс-доменных) | 12 (0) |

Ассеты: 4.81 МБ → 1.21 МБ. Каждый с проверенным SSIM.

Эквивалентность вёрстки проверялась покомпонентно: снимались координаты, размеры и
15 вычисленных стилей каждого элемента в обеих версиях. До правок расходились
**3 элемента из 342**, и все три — намеренно.

## История правок: что изменено относительно оригинала и почему

Всё ниже — дефекты **самого экспорта**, подтверждённые сравнением с оригиналом
(геометрия совпадала до пикселя, значит это не регресс оптимизации).

| Файл в `tools/` | Что чинит |
|---|---|
| `fix-cta.js` | Карточка CTA имела жёсткую `height: 760px`, а картинка холмов — `top: 430px` при `height: auto`. Сходилось ровно на ~1040px: шире — обрезало, уже — оставляло серую полосу. Холмы переведены в поток с `margin-top: auto` |
| `add-mobile-nav.js` | Ниже 1024px ссылки навигации скрывались через `display: none` без замены — разделы становились недостижимы. Добавлены бургер и выпадающее меню |
| `fix-mobile-nav-fit.js` | На 375px «Request access» переносилась в две строки и вылезала из капсулы — это ломалось ещё в оригинале. На ≤640px у логотипа остаётся только знак |
| `fix-mobile-cards.js` | Двум контейнерам на мобильном оставались `aspect-ratio: 1.1/1` + `padding: 40px`: внутрь помещалось 220px, а контенту нужно 363px. Одна карточка выпирала за родителя на 32px, у другой срезало нижнюю строку |
| `add-responsive-images.js` | LCP-элемент (крендель) отдавался в 1377px на бокс 228px. Добавлены `srcset` и мобильный вариант фона |
| `add-edge-light.js` | Не багфикс: бегущий по краю стеклянных карточек свет (запрошенная микроанимация) |

Скрипты идемпотентны и запускаются из корня репозитория. Они уже применены к `dist/`.

### Что пробовали и откатили

Была попытка показывать первый экран целиком (страница скрыта до загрузки ассетов,
потом плавное появление). **Замер показал, что это вредно:** FCP вырос со 124 мс до 4.1 с,
а LCP перестал фиксироваться вообще — Chrome не считает контентными элементы с
`opacity: 0`. Откачено. Связность загрузки решена иначе — уменьшением первого экрана
до ~196 КБ на мобильном.

## Открытые вопросы

- Проект в Vercel называется `dist`. В аккаунте уже есть проект `pretzel-labs.com` —
  решить, деплоить туда или переименовать текущий.
- Шейдер «рифлёного стекла» (`fluted-glass.js`) тянет ~122 КБ стороннего кода с esm.sh,
  включая собственную копию React. Загружается лениво, по `IntersectionObserver`.
  Замерено, что эффект **статичен** (три снимка за 2.4 с совпали побайтово), поэтому его
  можно запечь в картинку и убрать эти 122 КБ и 11 запросов. Компромисс: на нестандартных
  ширинах вместо пересчёта шейдера будет масштабирование битмапа.
- Мобильная адаптация исходного макета в целом сделана скрытием и переключением в одну
  колонку, но фиксированные высоты и пропорции внутри блоков под узкий экран не
  пересчитаны. Починены найденные случаи, не исключено, что есть ещё.
